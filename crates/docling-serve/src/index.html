docling-serve
HTTP conversion API
OpenAPI GitHub

Convert documents to Markdown, docling JSON, DocLang archives, LaTeX, HTML, Pandoc AST, or chunk records — over docling.rs, on this server. The API is described by /openapi.yaml (OpenAPI 3.1).

Try it

URL inputs are disabled on this server — start docling-serve with --allow-url-fetch to enable them (outbound fetch is an SSRF surface; see docs/SECURITY.md). Upload a file instead.
fetch images is disabled on this server — start docling-serve with --allow-url-fetch to pull external <img src> and embed them (it's an outbound-fetch / SSRF surface, so off by default; see docs/SECURITY.md).
PDF/image inputs run the ML pipeline — the first conversion loads the models (tens of seconds), repeats are fast. Markdown responses stream in as they convert. Picking several files converts them as one batch in the same format as one file: Markdown and text as one body with a dashed line between the documents, HTML as one page (<hr><hr><hr> between them), LaTeX as one document; JSON, chunks, Pandoc, VTT, dclx and images as a JSON results array.

    

  





API



  
MethodPathDescription

  
POST/v1/convert
      Convert an upload (multipart/form-data, a file part — the filename's
      extension selects the input format; several file parts convert as a batch in
      the same format as one file — Markdown / text with a dashed separator line between the
      documents, HTML one page, LaTeX one document; JSON, chunks, Pandoc, VTT, dclx and images
      as a JSON results array) or a URL (application/json:
      {"url": …, "file_name"?: …}). PDF/image responses carry an
      X-Docling-Confidence summary header; to=json bodies embed the full
      per-page confidence report.

  
POST/v1/convert/async
      The same request, answered immediately with {"task_id": …} — the job queues on
      the server's concurrency bound and reuses the warm pipeline.

  
GET/v1/status/{id}
      Async job status: pending | started | success | failure.

  
GET/v1/result/{id}
      Async job result — the same response the sync endpoint would have sent; kept until the
      result TTL (default 10 min) evicts it.

  
POST/v1/convert/file, /v1/convert/source
      Python docling-serve's own API, for the clients written against it (Open WebUI, n8n,
      Dify): files uploads or {"sources": […], "options": {…}} with
      upstream's option names, answered as its ConvertDocumentResponse
      (document.md_content, status, errors); /async
      variants, /v1/status/poll/{id} and /v1alpha/… aliases too.

  
GET/v1/configServer capabilities — allow_url_fetch, allow_local_images, the resolved models, and tesseract_languages (the stems ocr_lang may name under Tesseract) — which this page adapts to.

  
GET/healthLiveness probe.

  
GET/readyReadiness probe — 503 until --warmup finishes loading the ML models.

  
GET/openapi.yaml
      OpenAPI 3.1 description of this server — point Swagger UI, Redoc, or a client generator at it.

Examples


curl -F file=@paper.pdf  localhost:5001/v1/convert                 # Markdown (streams)
curl -F file=@report.docx 'localhost:5001/v1/convert?to=json'      # docling JSON
curl -F file=@sheet.xlsx  'localhost:5001/v1/convert?to=dclx' -OJ  # DocLang archive
curl -F file=@page.html   'localhost:5001/v1/convert?to=chunks'    # chunk records
curl -H 'content-type: application/json' \
     -d '{"url": "https://example.com/doc.pdf", "to": "md"}' \
     localhost:5001/v1/convert                                     # convert a URL

curl -F file=@a.pdf -F file=@b.docx \
     'localhost:5001/v1/convert?to=md'                             # batch → one Markdown, dashed line between documents

id=$(curl -F file=@big.pdf localhost:5001/v1/convert/async | jq -r .task_id)
curl localhost:5001/v1/status/$id                                  # pending|started|success|failure
curl localhost:5001/v1/result/$id                                  # the output, once done

curl -O localhost:5001/openapi.yaml                                # the API description
