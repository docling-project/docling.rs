W3C issues press release about developing Verifiable Credential Barcodes

Published on: Wed, 07 Oct 2026 17:50:00 +0000

In a press release we present the concept of real-time revocation that is being developed in the W3C Verifiable Credentials Barcodes specification to protect physical documents.

Recently the data theft of approximately 160 million drivers licenses from the US and Canada was reported and unfortunately, identity thieves will use this data to impersonate victims. Real-time revocation is needed to protect individuals against identity theft. The future of physical document security is being decided as we speak. W3C Verifiable Credential Barcodes are the solution - and the technology is open and free for all to use. The Verifiable Credential Barcodes technology we are building in the W3C Verifiable Credentials Working Group is already protecting millions of people from identity theft and fraud, with the potential to protect billions more. We want to make sure that government organizations and policymakers know that there is a free and open solution to this problem that is being designed for the public good.

Learn more in our press release: [Data breaches, identity theft, and revocation: a real-world case study on why W3C is developing Verifiable Credential Barcodes](https://www.w3.org/press-releases/2026/data-breaches-identity-theft-and-revocation-a-real-world-case-study-on-why-w3c-is-developing-verifiable-credential-barcodes/).

Updated Candidate Recommendation: Scalable Vector Graphics (SVG) 2

Published on: Tue, 06 Oct 2026 10:21:00 +0000

The SVG Working Group published Scalable Vector Graphics (SVG) 2 as a Candidate Recommendation Snapshot and invites implementations.

The [SVG Working Group](https://www.w3.org/groups/wg/svg/) invites implementations of an updated Candidate Recommendation Snapshot of [Scalable Vector Graphics (SVG) 2](https://www.w3.org/TR/2026/CR-SVG2-20261006/).

This is a fresh version of SVG2 with corrections, clarifications and improvements for more interoperability, in particular in implementations in web browsers.

This specification defines the features and syntax for Scalable Vector Graphics (SVG) Version 2. SVG is a language based on XML for describing two-dimensional vector and mixed vector/raster graphics. SVG content is stylable, scalable to different display resolutions, and can be viewed stand-alone, mixed with HTML content, or embedded using XML namespaces within other XML languages. SVG also supports dynamic changes; script can be used to create interactive documents, and animations can be performed using declarative animation features or by using script.

To help the group continue its work in updating this widely-used technology, comments are welcome via [Github issues](https://github.com/w3c/svgwg/issues/) by 1 **December 2026**.

W3C Workshop Report: The Future of ODRL

Published on: Thu, 24 Sep 2026 11:13:00 +0000

W3C is pleased to announce the report from the W3C Workshop on the Future of ODRL, held in July 2026 in London, UK, and online.

W3C is pleased to announce the [report](https://www.w3.org/2026/ODRLWS/report.html) from the [W3C Workshop on the Future of ODRL](https://www.w3.org/2026/ODRLWS/index.html), held in July 2026 in London, UK, and online.

Bringing together participants from standards organizations, industry, academia and the broader policy, data and rights communities, the workshop covered media, core semantics, banking and finance, data spaces, legal and regulatory applications, and new language features. It was explicitly positioned as a turning point for ODRL.

The emerging vision is considerably broader than simply producing another revision of the ODRL vocabulary. There was consensus to establish a new W3C ODRL Working Group set to work on ODRL 3.0 as a foundation for machine-readable, interoperable and increasingly machine-actionable policies, capable of operating across sectors and integrating with complementary standards for identity, provenance, legal information, data spaces and digital contracts.

The workshop's outcomes can be distilled into the following principal recommendations:

  1. Establish the new W3C ODRL 3.0 Working Group
  2. Start with use cases and explicit requirements
  3. Strengthen the formal semantics of ODRL
  4. Define conformance for policy-processing software
  5. Develop a comprehensive conformance test suite
  6. Adopt modular and potentially multi-level conformance
  7. Improve usability
  8. Position ODRL as an interoperability layer
  9. Investigate integration with complementary standards

The workshop's closing discussion confirmed that the workshop chairs would draft a Working Group charter. The intention is to socialize the charter at [TPAC 2026](https://www.w3.org/news-events/tpac/2026/) in Dublin, with the objective of moving into the next phase of ODRL 3.0 by the end of 2026.

W3C thanks JP Morgan Chase for hosting the workshop; thanks the [Program Committee](https://www.w3.org/2026/ODRLWS/index.html#program-committee), the [workshop speakers](https://www.w3.org/2026/ODRLWS/agenda.html), and all participants for making this event successful.

First Public Working Draft: Web Authentication: An API for accessing Public Key Credentials Level 4

Published on: Tue, 15 Sep 2026 06:07:00 +0000

This specification defines an API enabling the creation and use of strong, attested, scoped, public key-based credentials by web applications, for the purpose of strongly authenticating users.

The [Web Authentication Working Group](https://www.w3.org/groups/wg/webauthn/) has published a First Public Working Draft of [Web Authentication: An API for accessing Public Key Credentials Level 4](https://www.w3.org/TR/2026/WD-webauthn-4-20260915/). This specification defines an API enabling the creation and use of strong, attested, scoped, public key-based credentials by web applications, for the purpose of strongly authenticating users. Conceptually, one or more public key credentials, each scoped to a given WebAuthn Relying Party, are created by and bound to authenticators as requested by the web application. The user agent mediates access to authenticators and their public key credentials in order to preserve user privacy. Authenticators are responsible for ensuring that no operation is performed without user consent. Authenticators provide cryptographic proof of their properties to Relying Parties via attestation. This specification also describes the functional model for WebAuthn conformant authenticators, including their signature and attestation functionality. See [changes since Web Authentication Level 3](https://www.w3.org/TR/2026/WD-webauthn-4-20260915/#changes-since-l3).

Feedback is welcome via [GitHub issues](https://github.com/w3c/webauthn/issues).

First Public Working Draft: The Profiles Vocabulary

Published on: Thu, 20 Aug 2026 05:44:00 +0000

The Profiles Vocabulary is an RDF vocabulary created to allow the machine-readable description of profiles of specifications for information resources.

The [Dataset Exchange Working Group](https://www.w3.org/groups/wg/dx) has published today a First Public Working Draft of [The Profiles Vocabulary](https://www.w3.org/TR/2026/WD-dx-prof-1.0-20260820/). The Profiles Vocabulary is an RDF vocabulary created to allow the machine-readable description of profiles of specifications for information resources. It can be used to describe profile hierarchies wherein profiles of specifications may themselves have profiles indicated. It can also be used to link together multiple profile resources that make up a profile - guidelines, validation tools, schemas, term lists and so on - and it allows for those profile resources to be described with formats, roles, and digital artifacts.

The namespace for PROF terms is `http://www.w3.org/ns/dx/prof/` .
The PROF vocabulary, defined in OWL and encoded in RDF Turtle, is available at [prof.ttl](https://www.w3.org/TR/2026/WD-dx-prof-1.0-20260820/rdf/prof.ttl) .

Feedback is welcome via [GitHub w3c/dx-prof](https://github.com/w3c/dx-prof/).

Group Note Draft: Web Sustainability Guidelines (WSG) Impact Ratings

Published on: Tue, 18 Aug 2026 07:59:00 +0000

This document describes the impact ratings provided alongside Web Sustainability Guidelines (WSG).

The [Sustainable Web Interest Group](https://www.w3.org/groups/ig/sustainableweb) has published the first draft of a Group Note titled [Web Sustainability Guidelines (WSG) Impact Ratings](https://www.w3.org/TR/2026/DNOTE-wsg-ir-20260818/). The Web Sustainability Guidelines (WSG ) [Impact Measurement](https://w3c.github.io/sustainableweb-impact) resource defines a framework for assessing the impact of WSG guidelines across three categories: people, planet, and prosperity. Each guideline is assigned an impact rating (indeterminate, low, medium, or high) and a timeframe (short, medium, or long) indicating when the impact is expected to be observed.

These inputs are used to calculate an impact score for each guideline. The score helps organisations compare guidelines and prioritise actions based on relative impact and timeframe. Higher scores indicate higher impact achieved over a shorter timeframe. The resulting scores are included in the resource.

Where quantitative measurement is not possible, ratings are based on available research and expert input. Each guideline includes a rationale for its ratings and timeframe, and where appropriate, suggested metrics to support evaluation.

The user agent mediates access to authenticators and their public key credentials in order to preserve user privacy. Authenticators are responsible for ensuring that no operation is performed without user consent. Authenticators provide cryptographic proof of their properties to Relying Parties via attestation. This specification also describes the functional model for WebAuthn conformant authenticators, including their signature and attestation functionality.
